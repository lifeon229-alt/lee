# 마비노기 모바일(PC) 어비스 반복 자동화

화면 캡처 · 사진 비교(OpenCV `TM_CCOEFF_NORMED`) · Windows 한국어 OCR로 현재 화면을 확인하고, Interception 드라이버로 키보드·마우스를 입력한다.
전투는 게임의 자동전투가 담당하고, 이 프로그램은 **어비스 입장 → 결과 확인 → 다시 하기**와 보조 동작만 담당한다.
시간이 지났다는 이유만으로 다음 버튼을 누르지 않는다. 모든 입력은 대상이 실제로 확인된 뒤에만 보내고, 입력 후에는 버튼 소멸이나 다음 화면 등장으로 성공을 확인한다.

> **현재 상태:** 코드와 설정 골격, 엔진 흐름 단위 시험(51개)까지 완료. 실제 게임 화면 검증은 아직 하지 않았다.
> 아래 [필요한 자료](#필요한-자료)를 받아 저장된 화면으로 인식 위치부터 검증해야 한다.

## 구성

| 프로젝트 | 역할 |
|---|---|
| `src/AbyssBot.Core` | 설정(scenario/targets), 화면 인식(`Detector`: 판정과 위치만 반환, 입력 안 함), 실행 엔진(`AbyssEngine`: 모든 입력을 한 곳에서 순서대로), 화면 재분류, 자동 재개, 로그·오류 사진 |
| `src/AbyssBot.App` | Windows 전용: 게임 창 캡처, Windows.Media.Ocr 한국어 OCR, Interception 입력, WinForms UI, 화면 검증 도구 |
| `tests/AbyssBot.Tests` | 가상 게임 화면으로 엔진 흐름·재시도·오입력 방지 시험, 합성 이미지로 사진·색·OCR 규칙 시험 |
| `config/` | `scenario.json`(실행 순서·시간·선택 기능), `targets.json`(인식 대상), `images/`(비교 사진) |

실행 중에는 **실행 파일 옆**의 `scenario.json`, `targets.json`, `images/`만 읽는다. 시작할 때마다 다시 읽고, 로그에 경로와 수정 시각을 남긴다.
빌드할 때 `config/`의 파일이 더 새로우면 실행 파일 옆으로 복사된다. 실행 파일 옆 파일을 직접 고쳤다면 개발 폴더에도 반영해 둔다.

## 준비

1. Windows 10/11 x64, [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0) (빌드 시 .NET 8 SDK)
2. 한국어 OCR: 설정 → 시간 및 언어 → 언어 → 한국어 추가(광학 문자 인식 포함)
3. Interception: 드라이버를 `install-interception.exe /install`로 설치하고 **재부팅**, x64 `interception.dll`을 `AbyssBot.exe` 옆에 둔다.
   DLL 복사만으로는 설치가 끝난 것이 아니다. 프로그램의 **입력 장치 점검** 버튼으로 x64·DLL·드라이버·키보드/마우스 장치·관리자 권한을 확인한다.
4. 관리자 권한으로 실행된다(manifest).

```
dotnet build -c Release src/AbyssBot.App
# 결과: src/AbyssBot.App/bin/Release/net8.0-windows10.0.19041.0/win-x64/AbyssBot.exe
dotnet test tests/AbyssBot.Tests      # 엔진/인식 규칙 시험
```

## 좌표와 캡처 기준

- 영역 표기는 `[왼쪽, 위, 오른쪽, 아래]`이며 **[x, y, 너비, 높이]가 아니고 화면 절대좌표도 아니다.** 게임 창 캡처 이미지 기준 픽셀이다.
- 기준 캡처는 테두리·제목 표시줄을 포함한 게임 창 `816×1039`(`captureMode: WindowRect`, `GetWindowRect`).
  클릭 좌표 = 캡처 원점 + 검출 위치. 캡처와 클릭이 같은 원점을 써서 제목 표시줄 차이로 좌표가 밀리지 않는다.
- 프로세스는 Per-Monitor DPI 인식이라 좌표는 실제 픽셀이다.
- 캡처 크기가 기준과 다르면 **시작하지 않는다**(단순 비율 변환 안 함). 창 크기를 맞추거나 내 화면 기준으로 `targets.json`의 `baseline`과 영역을 다시 설정한다.
- 화면 복사 방식이므로 게임 창이 맨 앞(활성)일 때만 분석·입력한다. 다른 프로그램이 앞에 있으면 입력하지 않고 기다린다.

## 인식 규칙 (targets.json 초기값)

배점: OCR 2 · 사진 2 · 버튼 색 1. 같은 대상의 사진이 여러 장이면 **가장 높은 한 장만** 쓴다(합산 안 함).
사진은 탐색 영역을 사진 크기 절반만큼 넓혀 찾되 **사진 중심이 탐색 영역 안**인 후보만 인정한다.
OCR은 원본으로 먼저 읽고, 못 찾았을 때만 2배 확대해 다시 읽는다(좌표는 원래 크기로 환산). 비교 전 띄어쓰기를 제거한다.
사진과 OCR이 서로 다른 버튼을 가리키면 점수를 합치지 않는다(둘 다 각각 합격이면 충돌로 보고 입력하지 않음). 색만으로는 절대 합격하지 않는다.

| 대상 | 영역 | 판정 |
|---|---|---|
| `chat_input` | `[80, H-110, W, H]` | OCR '말하기' 포함 (메인화면 근거, 마을 이름·전체 문구 요구 안 함) |
| `menu_open` | `[W/2, 120, W, 700]` | 메뉴 이름 9개 중 **서로 다른** 이름 3개 이상 정확 일치 (원본·확대에서 같은 이름은 한 번만) |
| `abyss_menu` | `[450,280,640,420]` | OCR '어비스' 또는 `a_abyss.png` → 2점 |
| `dest_*` | `[100,480,700,900]` | 선택한 목적지 사진 하나만 검색 |
| `enter` | `[280,940,560,1020]` | 3점: OCR+사진, 또는 OCR/사진 + 초록·파랑 우세 |
| `result_touch` | `[240,930,600,1010]` | OCR '터치해' 또는 `touch.png`/`touch2.png` → 2점, 색 미사용 |
| `replay` | `[340,900,500,1039]` | OCR '다시하기' **와** 초록 배경 모두 필요(3점) |
| `skip` | `[600,55,816,145]` | OCR '대화넘기기'/'장면넘기기' |

색 판정: 후보 영역의 B·G·R 채널별 중앙값. 초록 = G−max(R,B) ≥ 60, 파랑 = B−max(R,G) ≥ 60.
OCR 글자 영역으로 잴 때는 가로 1.8배·세로 1.6배로 넓혀 탐색 영역 안으로 제한한다.
OCR 비교 방식: `contains`(포함), `fuzzy`(포함 + 3글자 이상이면 길이 차 ≤1·편집거리 ≤1), `exact`(단어/연속 단어가 정확히 같음).

사진 일치 기준 0.75는 초기값일 뿐이다. **화면 검증** 도구로 정상 화면과 비슷한 다른 화면의 점수를 비교해 사진마다 `threshold`를 정한다.

## 실행 흐름

```
최초 1회: 메뉴 열기 → 어비스 선택 → 목적지 선택 → 입장하기
반복:     전투 결과 대기 → (결과 터치) → 다시 하기 → 전투 결과 대기 …
```

- **메뉴 열기**: 이미 열려 있으면 ESC 안 누름. '말하기'가 보이면 ESC 한 번 → 700ms 뒤 확인. 메뉴 확인 전까지 ESC 반복 없음. 최대 15초.
- **어비스/목적지**: 클릭 후에도 남을 수 있어 사진 소멸이 아니라 다음 화면(목적지 배너 / 입장하기) 등장으로 성공 확인.
- **입장하기**: 확인 → 1초 대기(이 사이 보조 감시 입력 없음) → 다시 확인 → SPACE. 버튼이 연속 프레임에서 사라져야 성공. 재시도 때도 1초 적용.
- **전투 대기**: 결과창용 클릭·SPACE 없음. 우선순위: 재접속 → 대화·장면 넘기기 → 부활 → 음식 → 결과 문구. 한 캡처로 입력은 하나만, 입력 후 새로 캡처해 처음부터 판단.
- **결과/다시 하기**: 입력 후 400~650ms 뒤 재검사, 최초 입력 외 최대 3회 재시도. 한 프레임의 인식 실패를 소멸로 확정하지 않음(연속 2프레임).
  다시 하기가 60초 안에 나타나지 않으면 다른 버튼·빈자리를 누르지 않고 사진과 원인을 남겨 정지.
- 각 단계는 성공/실패/사용자 정지를 반환하고 **성공일 때만** 다음 단계로 간다. 입력 전달 실패, 게임 창 비활성, 캡처 후 창 이동, 커서 위치 불일치 시 입력하지 않는다.
- 목적지는 실행 중 잠긴다. 바꾸려면 정지 후 다시 시작(최초 입장부터).
- 목표 횟수(0=무제한)를 채우면 다시 하기를 누르지 않고 정상 완료 알림.

### 실패와 재개
- 시간 초과·실패 시 `errors/`에 화면 사진과 JSON(단계, 사유, 대상별 점수, 실제 OCR 문구, 색 판정, 마지막 입력과 시각)을 저장하고 약 3초 반복 경고음.
- 자동 재개(선택, 기본 꺼짐): 오류 후 10분 **그리고** 마지막 사용자 입력 후 10분이 지나고, 게임이 활성일 때 입력 없이 250ms 간격으로 화면을 재분류. 같은 단계가 3번 연속이면 알림+3초 카운트다운(입력 시 취소), 재개 직전 다시 확인. 한 실행에서 최대 3회.
- 재분류: 결과 문구→결과 확인, 다시 하기→다시 하기, 입장하기→입장, 목적지 목록→목적지 선택, 열린 메뉴→어비스 선택. 채팅창만 보이거나, 모르는 화면이거나, 근거가 충돌하면 재개하지 않는다(모르는 화면을 전투 중으로 간주하지 않음).
- F10/정지 버튼은 대기·재시도·카운트다운 중에도 즉시 멈추고 자동 재개 예약도 해제한다.

### 로그
`logs/abyss.log`(2MB × 5개 회전). 상태 변화와 주요 사건 위주이며 같은 메시지는 60초 안에 반복 기록하지 않는다. 오류 사진은 개수·용량 제한(200세트/300MB).

## 검증 순서
1. **현재 창 캡처 저장**(3초 뒤 게임 창 캡처 → `captures/`)으로 각 화면을 기준 크기로 저장한다.
2. **화면 검증…**으로 저장한 화면을 열어 대상별 점수·OCR 문구·색과 재분류 결과를 확인한다(입력 없음). 비슷한 다른 화면(버튼 없는 화면, 로딩, 부활 화면 등)도 함께 넣어 오검출이 없는지 보고, **사진 점수표 저장**으로 기준값을 정한다.
3. 목표 횟수 1로 **최초 입장 → 결과 터치**까지 한 번.
4. 목표 횟수 2로 **다시 하기 → 두 번째 전투 진입 → 결과**까지.
5. 위가 확인된 뒤 장시간 반복.

## 필요한 자료
`captures/`로 저장한 **전체 화면**(기준 크기)과 잘라낸 사진이 필요하다. 사진은 이름이 아니라 실제 내용을 확인해 등록한다.

- 메뉴가 열린 전체 화면(어비스 항목 포함), `a_abyss.png`
- 어비스 목적지 목록 전체 화면, 사용할 목적지 배너(`a_husang.png`/`a_kwanggi.png`/`a_moolgil.png`)
- 입장하기 버튼이 나온 화면, `a_enter.png`
- '화면을 터치해 주세요' 결과 화면, `touch.png`
- 다시 하기 버튼이 있는 보상 화면
- 선택 기능: 여기서 부활(행동불능) 화면과 부활 재료 부족·구매 안내 화면, 음식 사용 버튼이 보이는 화면(+버튼 역할 설명), 재접속 안내 화면
- 비교용: 버튼이 없는 화면, 로딩 화면, 전투 중 화면

부활·음식·재접속 대상은 실제 화면을 받기 전까지 `region: null`(미설정)이며, 기능을 켜도 시작 전 점검에서 막힌다.

## 기존 프로그램과 달리 하지 않는 것
- '불안정' 한 단어를 읽고 고정 좌표를 누르는 재접속 경로 — 안내 문구와 '다시 시도하기' 버튼이 모두 확인될 때만 검출 위치를 누른다.
- 부활 후 확인 없이 진행 — 부활 후 화면을 다시 보고 구매 안내가 나오면 구매하지 않고 정지한다.
- 모르는 화면에서 전투 대기(10분)와 복구를 최대 8번 반복 — 모르는 화면은 재개하지 않고 이유를 기록한다.
- 한 프레임 인식 실패를 버튼 소멸로 확정, 사진·OCR이 다른 버튼을 가리킬 때 점수 합산.
- 재화 구매·구매 확인은 어떤 경우에도 자동으로 하지 않는다.
